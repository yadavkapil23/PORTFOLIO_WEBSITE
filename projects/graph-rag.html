A portfolio-grade Graph Retrieval-Augmented Generation system that converts documents into a knowledge graph of entities and relationships, then answers multi-hop questions by traversing that graph.

The Concept

Vanilla RAG often struggles with complex, multi-hop reasoning because no single text chunk contains all the necessary facts. Graph RAG solves this by converting documents into a knowledge graph of entities and relationships. It can answer questions like "Which companies founded by ex-Apple employees compete with Apple?" by traversing the graph: Apple --employed--> Person --founded--> Company --competes_with--> Apple.

Pipeline Stages

  • Ingestion: Parses PDF/HTML/TXT into semantic chunks with overlap.
  • Extraction: LLM extracts entities and relationships from each chunk.
  • Entity Linking: Deduplicates entities (e.g., "Apple", "Apple Inc.", "AAPL" become one node).
  • Graph: Writes entities and relationships to a Neo4j knowledge graph.
  • Vector Store: Embeds chunks and stores them in Qdrant for semantic search.
  • Communities: Uses the Leiden algorithm to cluster entities into topics and generate LLM summaries.
  • Retrieval: Performs Local (entity hops), Global (communities), or Hybrid search.
  • Generation: Uses a structured prompt with citations to generate answers.

Tech Stack Highlights

The backend is built with FastAPI for async performance. For AI components, it uses Gemini 2.0 Flash for extraction, sentence-transformers (BAAI/bge-large-en-v1.5) for embeddings, and bge-reranker-v2-m3 for ranking. The knowledge graph is powered by Neo4j, and semantic search relies on Qdrant. The frontend provides interactive graph visualization using React and d3-force.
